# 赛博酒测 · 测测你的赛博醉酒等级

> 一个可以直接双击打开的单文件网页作品：三项荒诞体检 + 一份一本正经胡说八道的《赛博醉酒鉴定报告》。

- **作品形态**：单文件 `index.html`，HTML / CSS / JavaScript 全部内联
- **依赖**：零。不联网、不加载任何外部字体、图片、音频或库
- **运行**：双击 `index.html` 即可（也支持直接丢到任意静态服务器；`file://` 协议下功能完整）
- **适配**：桌面键盘 / 鼠标、移动端触屏（含安全区适配）均已处理

---

## 一、创作理念

醉酒测试这件事本身就充满黑色幽默：人越醉，越坚称自己没醉。于是我把"酒精测试"翻译成赛博语境——不是吹气，而是让你在三个荒诞的电子关卡里暴露小脑、手速和舌头的真实状态：走一条会自己扭动的霓虹小路、用篮子接住从天而降的酒杯与代码、盯着越来越模糊的绕口令决定自己还能不能读下去。整份作品的趣味不在"赢"，而在于**系统比你自己更清楚你醉了**：它用你亲手贡献的走歪次数、误接代码次数和反应耗时，为你颁发一个你无法反驳的称号。视觉上采用霓虹紫与电子青的暗色赛博朋克：扫描线、辉光、故障艺术字，让整个"体检中心"看起来既廉价又权威——这正是所有醉酒测试的气质。

## 三、玩法说明

### 通用流程

`开始界面 → 体检须知 → 3-2-1 倒计时 → 关卡一 → 结果简报 → 关卡二 → 结果简报 → 关卡三 → 结果简报 → 鉴定报告`

每一关前有「关卡简报」弹层说明规则，关卡后有「体检结果」弹层反馈本关真实数据，按空格 / 回车也可以推进弹层。

### 关卡一 · 走直线

| 项目 | 说明 |
| --- | --- |
| 目标 | 从起点走到 2600 像素外的「清醒之门」 |
| 操作（桌面） | 按住 `↑`（或 `W` / `空格`）前进；`←` `→`（或 `A` `D`）左右移动 |
| 操作（移动端） | **按住屏幕拖动**：手指位置即目标点，按住同时自动前进 |
| 判定 | 偏离霓虹小路记为一次「走歪」，出界期间前进速度减半，屏幕泛红并弹出「走歪了!」 |
| 难点 | 小路是两条正弦波叠加成的弯道，且随时间自我扭动；越接近终点弯道幅度越大、路面越窄 |
| 上限 | 60 秒未到终点则按当前完成度结算 |

### 关卡二 · 接酒杯

限时 35 秒，鼠标移动（移动端按住拖动）控制底部篮子，下落物含义如下：

| 物品 | 分值 | 额外效果 |
| --- | --- | --- |
| 🍸 酒杯（44%） | +10 | 青色粒子，连击 +1 |
| 🍺 啤酒（22%） | +8 | 醉意 +1，琥珀色粒子 |
| 🐱 猫（10%） | +25 | 稀有，紫色粒子 +「喵!」 |
| 💻 代码（24%） | **-15** | **屏幕剧烈抖动 + 全屏故障闪烁（hue-rotate / skew）**，连击清零 |

- 连击：每连续接住 5 个，倍率 +0.5，最高 ×3。
- 漏接酒杯会清零连击；生成节奏随剩余时间越来越少而加快，后期偶尔双发。
- 桌面端也可用 `←` `→` 微调篮子。

### 关卡三 · 读绕口令

- 屏幕显示一段绕口令，每个字独立扭曲：位移、旋转、缩放、模糊、色相偏移，**扭曲速度逐级加快**（第 8 轮约为第 1 轮的 3.7 倍），并且**每轮之内还会越来越快**。
- 在心里默读，读得下去就点「我还能读」；按钮会随难度轻微漂移（仍然点得到）。
- 每轮限时递减：7.0s → 6.0s → 5.2s → 4.6s → 4.0s → 3.5s → 3.1s → 2.8s，超时即判定「读不动了」，本项结束。
- 最高 8 轮，也可以点「读不动了…」主动认输。

### 鉴定报告

报告完全由前面三关的真实数据生成，包含：

1. **称号卡片**：内置 **21 种**称号（含兜底称号），配一句话标签与专属评语；
2. **五维雷达图**（Canvas 绘制，带生长动画）：清醒度 / 手速 / 语言能力 / 玄学体质 / 酒量；
3. **五项指标条**：每项标注数据来源（如「走歪 4 次 / 出界 16.2s」）；
4. **原始数据面板**：走歪次数、完成度、酒杯 / 啤酒 / 代码 / 猫 / 漏接、最高连击、绕口令轮数、平均反应耗时；
5. **赛博醉酒指数**：0–100 的醉度条 + `Lv.1 ~ Lv.9` 与六档区间描述（从「清醒得可疑 · 疑似代驾」到「酒精人形自走体 · 建议直接送修」）。

部分称号示例：`赛博醒酒中心名誉主任`、`清醒的赛博诗人`、`霓虹走钢丝大师`、`二进制微醺侠`、`内存溢出型醉汉`、`显卡烧毁型酒神`、`绕口令永动机`、`三杯倒型固态硬盘`、`酒后代码重构师`、`猫毛过敏型调酒师`、`举杯邀明月的赛博李白`、`走位飘忽的醉侠`、`深夜售货机前的哲学家`、`赛博酒精观测样本` 等。

## 四、技术实现说明

### 1. 单文件、零依赖

- 全部样式写在 `<head>` 的一个 `<style>` 里；全部逻辑写在 `<body>` 末尾的一个 `<script>` 里，整体包裹在 IIFE 中（`'use strict'`），不污染全局。
- 字体只用系统字体栈（`PingFang SC / Microsoft YaHei / Noto Sans CJK SC …`），**没有任何 `@font-face`、`<img>`、`fetch`、CDN 引用**。
- 音效使用 **WebAudio 现场合成**（`createOscillator` + `createGain` 包络），因此不需要任何音频文件；音频不可用时静默降级，不影响游戏。

### 2. 渲染与坐标系

- 关卡一、关卡二使用 **Canvas 2D**；关卡三与所有 UI 使用 **DOM + CSS 动画**。
- 画布按 `devicePixelRatio`（上限 2）缩放，逻辑坐标系与 CSS 像素一致，兼顾高分屏清晰度与移动端性能。
- 关卡一采用**世界坐标 + 相机**：角色沿世界 Y 轴前进，相机把角色固定在屏幕 65% 高度处，路径按屏幕逐行采样（每 7px 一点）绘制左右边界，再叠加中线虚线与双色辉光边线。
- 关卡二在渲染前叠加一次随机平移实现**屏幕抖动**（命中代码时触发并按帧衰减），同时对舞台容器加 CSS 类触发 `hue-rotate / skew / invert` 的**故障艺术闪烁**。
- 关卡三把绕口令拆成逐字 `<span>`，每帧写入 `transform` 与 `filter: blur() hue-rotate()`，配合 `will-change: transform, filter` 让合成层复用。

### 3. 关卡判定的关键实现

- **走歪计数**：比较角色横坐标与路径中轴的偏差是否超过（半宽 − 角色半径），只在「界内 → 界外」的那一帧计一次，避免持续出界被重复计数；出界期间累计 `offMs` 用于报告。
- **输入统一**：桌面用 `keydown/keyup` 维护按键状态表；移动端用 Pointer Events（`pointerdown/move/up/cancel` + `setPointerCapture`），拖动位置直接作为横向目标点，键盘与触屏共用同一套速度积分逻辑。
- **接住判定**：物品进入「篮子高度带」且水平距离小于（篮半宽 + 物品半径 × 0.55）即命中，判定后立即标记 `dead` 并统一过滤，避免同一物品重复计分。
- **伤害节奏**：生成间隔由 `0.62s` 线性收紧到 `0.28s` 并按剩余时间加成，后期 35% 概率双发。

### 4. 报告算法（全部基于真实表现，非随机）

五项指标各自有明确来源，取值范围统一归一化到 0–100：

```
清醒度   = 100 − 走歪次数×9 − 出界秒数×3.5 − (未到终点 ? 16 : 0)
手速     = clamp(接酒杯得分 × 0.20)
语言能力 = 绕口令轮数×11 + clamp(20 − 平均反应ms/300) + (读满 8 轮 ? 10 : 0)
玄学体质 = 18 + frac(sin(走歪×12.9898 + 猫×78.233 + 轮数×37.719
                        + 啤酒×4.77 + 代码×9.13 + 反应ms×0.013) × 43758.5453) × 66 + 猫×3.5
酒量     = 24 + 啤酒×7 + 绕口令轮数×3.5 + (走到终点 ? 14 : 0) + 酒杯×0.3 − 误接代码×3
醉度     = clamp(100 − (清醒×0.38 + 手速×0.20 + 语言×0.22 + 酒量×0.20) × 1.15 + (玄学−50)×0.12)
```

- **玄学体质**看起来最"玄"，但它是一个**由真实操作数据派生的确定性哈希**：同样的表现永远得到同样的分数，不是 `Math.random()`，因此报告可复现。
- **称号判定**：21 个称号各自带一个打分函数（例如「霓虹走钢丝大师」要求"走到终点且走歪 ≤ 1 次"，「猫毛过敏型调酒师」对抓到的猫数量加权），系统对所有称号打分后**取最高分**，并保留一个基础分恒为 1 的兜底称号，保证任何离谱表现都能拿到称号。
- **雷达图**为 Canvas 手绘：4 层同心五边形网格 + 5 条轴线 + 数值标签 + 径向渐变多边形，进入报告页时有 850ms 的 `easeOut` 生长动画。

### 5. 视觉与响应式

- **赛博朋克视觉**：霓虹紫 `#a06cff` / 电子青 `#31e8ff` / 品红 `#ff2f8e` / 故障红 `#ff3b5c`；全局 `#crt` 扫描线纹理 + 暗角、`#beam` 缓慢下移的扫描光束、`text-shadow` 与 `shadowBlur` 双层辉光。
- **故障艺术字**：`.glitch` 用 `::before/::after` 复制 `attr(data-text)`，分别做上下半区 `clip-path` 裁切与不规则位移动画，标题在运行时会同步更新 `data-text`。
- **移动端适配**：`viewport-fit=cover` + `env(safe-area-inset-*)` 安全区；`clamp()` 控制标题与字号；所有触控画布 `touch-action:none` 防止页面跟着滚动；按钮最小高度 46px；报告页在窄屏下由两栏自动折叠为单栏；`resize/orientationchange` 会重新适配画布并保留当前进度（不重置游戏）。
- **性能取舍**：粒子与飘字使用对象池式数组 + `filter` 回收；雨丝固定 46 条；扭曲文字每帧只写样式不触发重排；暂停切到后台时 `requestAnimationFrame` 自动停止，`dt` 上限 50ms 防止回前台"瞬移"。

### 6. 兼容性

- Chrome / Edge / Firefox / Safari 及主流移动浏览器（需支持 Canvas 2D、Pointer Events、`clamp()`、CSS `filter`）。
- 不支持 Pointer Events 的老浏览器仅影响拖拽操作，仍可用键盘完成三关（关卡三本身只需点击）。
- `navigator.clipboard` 不可用时（如部分 `file://` 场景）自动回退到 `textarea + execCommand('copy')`。
